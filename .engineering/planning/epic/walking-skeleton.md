## Goal

The owner, 2026-11-27 about 08:35 CET (relayed by the host operator): "start building weft". First
code of weft, built from `ess/`. Design: `docs/implementation.md` (decisions A1-A7 and D-split A,
the owner, 09:26 CET: weft's domains are its own Rust generated by ESS; Spindle runs only
`ess-system` workloads, a later epic).

## Outcome

1. One Cargo workspace at the repository root, Rust pinned by `rust-toolchain.toml`, cargo-nextest
   with a 60 s kill per test and the step under 120 s, run by `slot task check` and CI.
2. The code ESS synthesizes (`ess generate synthesize --target rust`) from an input that
   `tools/synth-input.sh` derives from the unmodified `ess/` by removing the constructs of E1-E3
   (§ Gaps), each removal naming its ESS story,
   committed under `generated/` with a digest of `ess/`; a fast check compares the digest; the
   `slow` lane regenerates and compares bytes.
3. A control host: one weft binary serving the generated HTTP surface of `weft-api` and
   `weft-control` on loopback, with the storage port on SQLite, the context port (clock,
   identities, `external:` deciders), and the obligations on the skeleton's path written by hand;
   every other obligation answers a declared not-implemented refusal.
4. `weft-controllers`: the level and time steps of the skeleton's path that no binding runs
   (the scheduler placing an instance, the repair that reassigns an unassigned placement), in the
   control host process.
5. `weft-agent` (crate; the generated code already has a `weft-node` crate): dials the control host, joins with a token (`JoinNode`), opens its session, reads
   its assignment, starts the instance's code snippet confined by `substrate-daemon` (no root),
   and reports it running (`RecordInstanceRunning` path).
6. An end-to-end test under 60 s: tenant, account, workload, `PlaceInstance`, the snippet runs
   confined, the instance's view answers running.
7. ESS's conformance suite for the skeleton's domains, committed with a digest of its sources, run
   by ESS's runner against the control host's HTTP surface in the gate; its counts recorded as
   coverage; regeneration in the `slow` lane.

## Not in this epic

- Spindle and `ess-system` workloads, mTLS on the node channel, PostgreSQL, more than one node,
  weft-edge traffic, the CLI surface, load tests, VMs, GPUs.
