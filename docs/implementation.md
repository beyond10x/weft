# weft implementation design

Status: draft, 2026-11-27. Order: the owner, 2026-11-27 about 08:35 CET, "start building weft",
relayed by the host operator. The specification under `ess/` (ESS 0.99.2, `ess/37`) is the source;
this document maps its components to code.

## Decisions (2026-11-27)

The host operator decided A1, A4 and A6 at 08:36 CET. The owner picked A2, A3 and A5 at about
08:40 CET ("A: all 3 defaults"). The owner then revised A2, A3 and A7 at 09:26 CET with D-split A:
"the cloud should not entirely depend on [Spindle] ... the part where we just want to deploy ESS
stacks, this most likely does depend on [Spindle]". The host operator relayed both picks.

- **A1 language**: Rust.
- **A2 how the domains run**: weft's own Rust, generated by `ess generate synthesize --target
  rust` from the unmodified `ess/`. weft writes by hand what synthesis leaves as an obligation,
  the ports, and the controllers. Spindle does not run weft's domains.
- **A3 process layout**: the control host is one weft binary, `weft-api` and `weft-control` in one
  process (the sketch's `local` placement, `docs/domain-sketch.md` § Components). A node is
  `weft-agent` plus `substrate-daemon`.
- **A4 store**: SQLite behind the generated storage port.
- **A5 node join**: the node dials the control host over HTTP on loopback with a join token from
  `ProvisionPoolNode` and sends `JoinNode`. It reads its assignments from the control host, and no
  inbound port opens on the node. mTLS is a later story.
- **A6 confinement**: `substrate-daemon` over its Unix socket, through `b10x-substrate-sdk` at an
  exact git rev.
- **A7 conformance**: ESS's conformance runner against weft's own HTTP surface; the suite
  committed with a digest of its sources and regenerated in the `slow` lane.
- **Spindle**: the runtime for workloads whose package is an `ess-system`
  (`docs/domain-sketch.md:344`, "an ESS system, run by Spindle"). A node starts `b10x-spindle`
  under substrate for such a workload. This is the next epic, not the walking skeleton.

## Measured (2026-11-27, at `3b28c47`)

- `ess generate synthesize --path ess --target rust` on the unmodified `ess/` exits 1 with "rust
  target cannot emit this workspace" and 51 refusals of 3 kinds (§ Gaps E1-E3).
- On a scratch copy with E1-E3 removed (8 `one_time_response` lines deleted, 41 per-refusal
  failure policies set to `retry`, binding `r1-create-replica` dropped), synthesis exits 0 in 15 s:
  "3019 capabilities: 2735 generated, 284 obligation(s), 0 refused", 59 artifacts.
  - Crates and their Rust line counts: `weft-types` 95,042; `weft-server` 171,915 (the HTTP
    surface); `weft-control` 8,432; `weft-system` 5,556; `weft-api` 1,849; `weft-edge` 324;
    `weft-node` 258.
  - Obligations: 252 command behaviours, 28 view queries, 3 conversions, 2 capabilities and 1
    binding transformation. An obligation is a function with a contract that weft writes by hand.
  - Ports weft provides: `storage` (one per entity: load, store, replace, remove, list) and
    `context` (caller attributes, assigned identities and values, and the decision of each
    `external:` branch).
- substrate 0.29.0 (`beyond10x/substrate`, Apache-2.0, public): confined execs on one Linux host
  without root (bubblewrap, user/mount/PID/IPC/UTS/network namespaces, cgroup v2, seccomp). HTTP
  over a Unix socket, Rust SDK `b10x-substrate-sdk`. Exec states `accepted | running | exited |
  cancelled | expired | unknown`. `substrate-daemon`, `/usr/bin/bwrap` and `/usr/bin/socat` are on
  this host.

## Shape

```
  weft CLI / tests ──HTTP──▶ weft control host (one Rust binary)
                             │ weft-server: generated routes of weft-api + weft-control
                             │ generated behaviours + weft's obligations (crates/weft-impl)
                             │ storage port: SQLite; context port: clock, ids, deciders
                             │ controllers: level and time steps (crates/weft-controllers)
                             │ node-channel endpoint: stamps received_at (ControlPlane)
                             └──────────────▲──────────────────────────────────
                                            │ node dials out (HTTP, join token)
                             weft-agent (Rust)┘ reads its assignments, reports observations
                                  │ Unix socket, b10x-substrate-sdk
                             substrate-daemon (no root) ─▶ confined snippet
```

- Generated code under `generated/` (the synthesis output), committed with the digest of
  `ess/`. A fast check compares the digest; regeneration runs in the `slow` lane and compares
  bytes (`~/beyond10x/AGENTS.md` § Tests stay fast). Generated files are never edited by hand.
- weft's own crates under `crates/`: `weft-impl` (obligations and ports), `weft-controllers`,
  `weft-agent` (the node agent; the generated code owns the name `weft-node`), `weft-bin` (the control host binary), `weft-testkit`.
- The skeleton implements the obligations on its path. Every other obligation answers a declared
  "not implemented" refusal, and the conformance counts show each one as not executed.

## Walking skeleton (wave plan in the AEP store, `epic:walking-skeleton`)

Goal: one control host and one node on this machine; a tenant and an account; `PlaceInstance`
leads to a confined code snippet that runs and is recorded running; ESS's conformance suite runs
against weft's HTTP surface with its counts recorded.

The command path is the list in `sim/experiments/full-setup.yaml:38-70`, from CreateCloud to
RecordInstanceRunning.

Budget of `slot task check` (one pool job, killed after 10 min): the test step ends at 120 s,
conformance at 110 s, and the gate self-test within 30 s. The rest is build time.

## Gaps

ESS's Rust target, filed in ESS's store 2026-11-27 09:33 CET (ESS commit `bfb32ee3d6`; no fix in
0.99.3-0.99.8). The skeleton does not wait (host operator, 09:28 CET): `tools/synth-input.sh`
derives the synthesis input from the unmodified `ess/` without these constructs, and hand-written
code restores them on the skeleton path only, each piece naming its ESS story:

- E1: `story:the-rust-target-writes-a-one-time-response-outcome-as-an-obligation-that-carries-its-contract-instead-of-refusing-the-workspace`
- E2: `story:the-rust-dispatch-selects-a-binding-failure-policy-per-refusal-of-the-invoked-command-and-counts-attempts`
- E3: `story:rust-binding-wraps-a-plain-copy-into-an-optional-member`

What each one refuses:

- E1: `one_time_response` is refused in 8 outcomes: `access.CollectLoginToken/issued`,
  `CreateApiToken/created`, `ExchangeFederatedToken/exchanged`, `StartLogin/started`,
  `identity.ExchangeToken/exchanged`, `infrastructure.IssueJoinToken/issued`,
  `ProvisionNode/provisioned` and `ProvisionPoolNode/provisioned`. Wanted: obligations with the
  one-time contract, which weft writes by hand.
- E2: a per-refusal `on_failure` policy is refused in 41 bindings ("this target's dispatch answers
  every failure with one policy").
- E3: binding `r1-create-replica` maps `Integer` into `Optional<Integer>` and `ServiceId` into
  `Optional<ServiceId>` ("needs an explicit target representation").
- G5: ESS synthesis of the conformance suite for the `workloads` subset ran over 30 min
  (`docs/ess-gaps.md` gap 24). The suite is synthesized once and timed; if it exceeds the pool's
  30-minute bound, the story reports the time and the suite is cut to the domains that synthesize
  within it.
