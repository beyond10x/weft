---

Checked against `main` on 2026-11-27. **Shipped** exists in the repository and is held by the gate.
**Planned** is not built; nothing planned runs today.

| Area | Item | Status | What it means |
|---|---|---|---|
| Specification | [The domain model](specification/read.md) | shipped | 23 domains in 10 layers under `ess/`, valid with `ess specify validate --path ess --strict-requires` (ess 0.99.2). |
| Specification | [Components and bindings](specification/read.md#components-and-bindings) | shipped | `weft-api`, `weft-control`, `weft-node` and `weft-edge` in `ess/components.yaml`, with the reconciliation loops as bindings. |
| Specification | [Layer rule](specification/layers.md) | shipped | A domain names only domains of its own or a lower layer; `tools/check-layers.sh` holds it in the gate. |
| Specification | [Protocols](specification/read.md#the-files) | shipped | The node channel and the exec channel as `ess-protospec/1` documents under `protocols/`. |
| Specification | [HTTP and CLI surfaces](specification/read.md#the-files) | planned | The user API as `ess-http/1` and the CLI as `ess-cli/2`. No document exists yet. |
| Simulator | [weft-sim explore](simulator/run.md#explore) | shipped | Random command sequences over the whole specification, with system invariants checked after each step. |
| Simulator | [weft-sim simulate](simulator/run.md#simulate) | shipped | Experiments with a setup, traffic, faults and controllers driven as the reconciliation loops would. |
| Simulator | [weft-sim replay](simulator/run.md#replay) | shipped | Replays one recorded walk and checks the invariants after every step. |
| Gate | [`task check`](operate/troubleshoot.md#the-gate) | shipped | Validation, layers, stamped time, the CI path filter and the simulator's tests, locally and in CI. |
| Implementation | [Generated domain code](run/control-host-and-node.md) | planned | weft's domains in Rust, generated by ESS from the specification. |
| Implementation | [Control host](run/control-host-and-node.md) | planned | The binary that runs `weft-api` and `weft-control`. |
| Implementation | [Node agent](run/control-host-and-node.md) | planned | The node agent, `weft-node`, on substrate. |
| Implementation | [ESS systems as workloads](run/deploy-a-workload.md) | planned | An ESS system deployed as a workload, run by Spindle. |
| Implementation | [weft CLI](run/deploy-a-workload.md) | planned | The `weft` CLI: login, contexts, deploy, plan, logs and secrets. |

The landing page reads the same list from `website/data/status.json`.
